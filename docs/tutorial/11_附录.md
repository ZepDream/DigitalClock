表注：

- 58 个 I/O 的构成：`PO` 16 + `PI` 16 + `PIO` 16 + 核心键 4 + 时钟 1 + 蜂鸣器 1 + LED 4 = 58。
- **段序（实测，容易踩坑）**：板上 `PO[0]=a`、`PO[1]=b` … `PO[6]=g`、`PO[7]=dp`，也就是 `PO[7:0]` 是 **dp,g,f,e,d,c,b,a**；
  而本设计内部约定 `seg_n[7:0] = {g,f,e,d,c,b,a,dp}`。两者相反，因此 `.qsf` 里 8 条 seg 引脚是按**相反顺序**锁定的：
  `seg_n[7]`(g)→`PO[6]`=D1、`seg_n[6]`(f)→`PO[5]`=B3 …… `seg_n[0]`(dp)→`PO[7]`=C2。
  手册正文写“`PO[7:0]` 依次接 g、f、e、d、c、b、a、point”，与实测不符；按手册正文锁会显示成“字符像但缺段/多段”。
  验证方法：用 `test/seg_check` 工程（每 1 秒点亮一段），看 `PO[0]` 先亮哪一段。
- `PI` / `PIO` 在模式 9 下由动态配置板的 CPLD 驱动，FPGA 侧只能做输入，不能清零，也不能改成输出。
- 核心板按键加了 `WEAK_PULL_UP_RESISTOR ON`，所以不按时读到 1。
- 若核心板换成 `10CL010YU256C8G`，只改器件型号，本表引脚不变。
- 引脚 CSV 只有 `signal,fpga_pin` 两列，不区分位序；位序以本表为准。

## 11.2 编译与仿真报错速查

| 报错 / 现象 | 出现场合 | 原因 | 解决 |
|---|---|---|---|
| `Error: Can't find design unit work.xxx` | ModelSim `vsim` | 模块没编译进 work，或单元名拼错 | 先 `do compile.do`；`vsim` 的单元名必须等于 module 名，不是文件名之外的别名 |
| `Error (10170): Verilog HDL syntax error at ... near text "..."` | Quartus 编译 | 少分号、括号或 `begin/end` 不配对、混入中文标点 | 双击 Messages 跳到行号，先看**上一行**末尾；把 `；` `，` 换成半角 |
| `Error (10028): can't resolve multiple constant drivers for net "xxx"` | Quartus 编译 | 同一个信号在两个 `always` / `assign` 里被赋值 | 只留一个驱动源；组合逻辑合并进一个 `always`；检查顶层有没有重复 `assign` |
| `Warning (10230): truncated value with size ...` | Quartus 编译 | 赋的值比目标位宽宽，高位被截掉 | 给常量补位宽（如 `26'd0`）或显式截位；别用不定位宽的十进制常量 |
| `Critical Warning: No clocks defined in design` | Quartus 时序分析 | `create_clock` 没写，或时钟没有真正接进设计 | 确认 `DigitalClock.sdc` 第 2 行 `create_clock -period 20.000 [get_ports {clk50}]` |
| `Error: Top-level design entity "digital_clock_top" is undefined` | Quartus 编译 | 顶层名拼错、文件没加进工程、module 名和文件名不一致 | 查 `.qsf` 的 `TOP_LEVEL_ENTITY`；`Settings → Files` 加 `rtl/digital_clock_top.v` |
| `vlog: Module 'xxx' not found` | ModelSim 编译 | 漏编某个 `rtl/*.v`、编译顺序不对、例化名拼错 | 把 `rtl/*.v` 全编（`run_sim.bat` 用 `for` 循环自动做）；查例化名和端口名 |
| `vsim: Failed to find design unit work.tb_xxx` | ModelSim | work 库是旧的或空的，或 `vsim` 名字写错 | 重建库：`vdel -all`、`vlib work`、`vmap work work`，再 `do compile.do` |
| 仿真没有波形 | ModelSim | 没 `add wave`、没 `run`，或信号被 `vopt` 优化掉 | `do wave_all.do` 后 `run -all`；必要时 `vsim -voptargs=+acc` |
| `$finish` 立即结束 | ModelSim | `initial` 里提前 `$finish`，或第一条断言就失败退出 | 把 `$finish` 移到测试末尾；看 Transcript 里第一条 `ERROR`，那才是真问题 |
| `Library work not found` / work 库找不到 | ModelSim 启动 | 工作目录不在 `sim/`，或没建 work 库 | `cd sim`；`vlib work` + `vmap work work`；或直接 `do compile.do` |
| ModelSim 打不开 / 没有 license | 启动 ModelSim | 用了 ModelSim-Altera 但 license 没配；`modelsim.ini` 指向错误 | 用 `sim\run_sim.bat`（已把 `MODELSIM` 指向 `modelsim_ase\modelsim.ini`）；或单独启动 ModelSim-ASE |
| `Error (12007): Pin "M15" is already assigned to ...` | Quartus Fitter | 同一引脚分配给了两个信号 | Pin Planner 删重复；在 `.qsf` 里搜 `set_location_assignment` 核对 |
| `Error (10137): object "xxx" on left-hand side ... must have a variable data type` | Quartus 编译 | 在 `always` 里给 `wire` 赋值，或 `output wire` 却当寄存器用 | 声明成 `reg`；端口写成 `output reg` |
| `Warning (169177): ... 3.3-V interfaces` | Quartus Fitter | 3.3 V LVTTL 电平接口提示，不是错误 | 本实验箱就是 3.3 V，可以忽略；不要为了消警告改成 2.5 V |
| `Error: Can't find file 'rtl/xxx.v'` | Quartus 编译 | 文件被改名/移动，或 `.qsf` 里的相对路径不对 | 在 `Settings → Files` 里删掉再重新加；相对路径以 `.qpf` 所在目录为基准 |
| `Warning: Some output pins have no driver` | Quartus Fitter | 某个输出端口在顶层没连、或模块输出名拼错 | 在 RTL Viewer 里找悬空脚；核对端口名大小写 |
| Fitter 进度条卡住或跑很久 | Quartus Fitter | 多线程与杀毒软件实时扫描抢资源，或设计规模变大后正常耗时 | 看 Compilation Report 是否仍在输出；临时把 `.qsf` 第 10 行 `NUM_PARALLEL_PROCESSORS` 改成 1；把工程目录加进杀毒白名单 |
| 编译通过但 `.sof` 没更新 | Quartus | 只跑了 Analysis & Synthesis，没跑全编译 | `Processing → Start Compilation`（不是 Start Analysis & Synthesis） |

## 11.4 练习答案要点

以下是第 01~10 章练习的答案要点，不给完整代码。每条写清“改哪个文件、哪几行、为什么”。

### 第 01 章 从 C 到 Verilog

1. **C 顺序执行，Verilog 描述并行硬件**：`always @(posedge clk)` 块里的语句是“同一个时钟沿同时发生”，不是一行行跑。
   看 `clk_gen.v`：四个计数器在同一个 `always` 里各自计数，写成 C 就得开线程或写状态机。
2. **为什么用 `<=`**：非阻塞赋值在时钟沿“同时”更新，`sync0 <= nibble_in; sync1 <= sync0;` 才能得到真正的两级同步。
   改成 `=` 后 `sync1` 直接拿到 `nibble_in`，少一级同步，亚稳态风险回来了。
3. **module 与 function 的区别**：module 有端口、要被例化、对应一块独立硬件；function 没有端口、只能做组合计算、在 `always` 里调用。
   例子：`seg_decode` 是 module；`key_ctrl` 的 `next_mode`、`time_counter` 的 `inc_time` 是 function。
4. **位宽与溢出**：`reg [23:0]` 是无符号位向量，没有 C 的 `int` 溢出语义；`+ 1'b1` 会自动扩展到 24 位，超范围由设计者自己处理。
5. **同一个功能两种写法**：C 里写函数处理“一次调用”，Verilog 里既可以写 function（组合）、也可以写 module（并行硬件）。
   看到 `function` 就按“纯计算”理解，看到 `module` 就按“又一块电路”理解，两者不能混着套。

### 第 02 章 认识这个工程

1. **模块职责怎么分**：顶层只做复位和连线；`key_input` 只汇总按键；`key_ctrl` 只做状态机；四个功能模块各自维护数据；`display_ctrl` 只负责显示。
   判断标准：改一个功能时，理想情况只动一个文件。
2. **哪些文件该进 git**：`rtl/`、`sim/*.v`、`sim/*.do`、`sim/*.bat`、`constraints/`、`docs/` 要进；`db/`、`incremental_db/`、`output_files/`、`sim/work/`、`*.vcd`、`*.wlf`、`*.sof` 不进。
   判据：能不能由源码加脚本重新生成；能重新生成的不进，`.gitignore` 已经按这个原则写好。
3. **工程三件套**：`.qpf` 只记工程名和版本；`.qsf` 记器件、文件列表、引脚、I/O 标准；`.sdc` 记时钟约束。三个都要进 git，缺一个别人就编不出同样的结果。
4. **为什么一个模块一个文件**：Quartus 按文件名找模块，`.qsf` 第 13~27 行逐个列 `VERILOG_FILE`；文件名等于模块名，能避免 `Can't find design unit`。

### 第 03 章 Quartus 全流程

1. **新建工程**：`New Project Wizard` → 选目录 → 工程名 `DigitalClock` → 顶层实体 `digital_clock_top` → 器件 `Cyclone 10 LP` / `10CL006YU256C8G`。
   顶层实体名必须和 `rtl/digital_clock_top.v` 的 module 名一致，否则报 `Top-level design entity is undefined`。
2. **加文件**：15 个 `rtl/*.v` 加 `DigitalClock.sdc`；SDC 在 `Settings → Timing Analysis` 里能看到才算加对。
3. **引脚锁定**：Pin Planner 图形化点，或直接写 `set_location_assignment`；改完必须 `Start Compilation`，引脚信息才会进 `.sof`。
   对照 `constraints/pin_assignments.csv` 和 11.1 表，58 条一条不能少。
4. **编译结果判读**：0 error、1 warning（AN447 3.3 V 提示）、1,584 LE（25%）、680 registers、58 I/O；Fitter 成功才会生成 `output_files/DigitalClock.sof`。
5. **三个常见坑**：顶层名拼错、文件没加进工程、同一引脚分配两次（`Error (12007)`）。

### 第 04 章 顶层与连接

1. **端口连接**：`.clk(clk50)` 的名字必须和子模块端口名完全一致；漏写某个端口就是悬空，Quartus 往往只给 warning 不报错。
   检查方法：编译后看 `Warning: ... has no driver` 或在 RTL Viewer 里看有没有悬空脚。
2. **参数例化**：`clk_gen #(.CLK_FREQ(CLK_FREQ), .SIM_FAST(SIM_FAST)) u_clk_gen (...)`；参数在例化处覆盖，不改子模块里的默认值。
   仿真时 `SIM_FAST(1)`，上板时必须回到 0。
3. **位宽匹配**：`key_press[7:0]` 对 `key_ctrl` 的 `input [7:0]`；`pi_in` 是 16 位，整条接进 `key_input`，模块内部再切成 4 个 nibble。
   位宽不一致会触发 `Warning (10230)`，高位被悄悄截掉。
4. **一个信号只能有一个驱动**：`edit_load` 只由 `key_ctrl` 产生，`time_counter`、`alarm_ctrl`、`countdown` 只读不写，否则报 `Error (10028)`。
5. **改连线的最小步骤**：先在顶层找 `.端口名(信号名)`，再查信号在 top 里声明的位宽，最后编译看有没有悬空警告。
   连线错误在仿真里常常表现为“某个输入恒 0/X”，比编译错误难查，改完先跑 `run_sim.bat` 再上板。

### 第 05 章 模块解读（一）

1. **消抖时间改哪里**：`nibble_key.v` 的 `parameter DEBOUNCE_MS = 20`（单位 ms，靠 `tick_1khz` 计数）；`core_key.v` 的 `DEBOUNCE_MS` 同理。
   改例化处 `#(.DEBOUNCE_MS(30))` 或改默认值；`cnt` 只有 5 位，改到 50 就必须把 `cnt` 扩成 6 位，否则永远数不到 49，按键会完全没反应。
2. **键位交换**：在 `key_input.v` 换 `.nibble_in(pi_in[3:0])` 和 `.nibble_in(pi_in[7:4])`，改的是“物理键到逻辑键”的映射；或在 `key_ctrl.v` 换 `key_press` 下标，改的是功能。两处只需改一处。
3. **连发参数**：`core_key.v` 的 `REPEAT_DELAY_MS=500`、`REPEAT_RATE_MS=100`、`REPEAT_EN`；K2/K3 例化时 `REPEAT_EN(1)`，K1/K4 是 0。
   嫌慢就减小 `REPEAT_DELAY_MS`；想关连发就把 `REPEAT_EN` 改 0。
4. **一次按键一个脉冲**：`press` 只在 `tick_1khz` 分支里置 1，下一个时钟周期被开头的 `press <= 1'b0` 清掉，所以宽度是 1 个 50 MHz 周期。
   这也是 `key_ctrl` 里用 `if (key_press[k])` 就能“只执行一次”的原因。

### 第 06 章 模块解读（二）

1. **闹钟比较**：`alarm_ctrl.v` 的 `assign match = en_reg && (time_bcd == alarm_reg);`，`alarm_trigger <= match & ~match_d` 保证只响一次。
   想改成“响 10 秒”，要改 `beep_ctrl.v` 的节奏，不是改这里。
2. **秒表清零**：`stopwatch.v` 的 `else if (clear)` 分支把 `min/sec/cs` 清 0 并 `run_reg <= 0`；`clear` 来自 `key_ctrl` 的 `MODE_ST` 分支（键 2）。
   想“清零但继续跑”，就把 `run_reg <= 0` 去掉。
3. **倒计时启动条件**：`countdown.v` 的 `start_pause` 分支里只有 `(!expired_reg) && (remain_reg != 0)` 才 `run_reg <= 1`。
   所以显示 `00:00:00` 时按键 1 没反应；默认 `00:05:00` 写在复位分支的三条赋值里。
4. **提示音节奏**：`beep_ctrl.v` 的 `ALARM_ON_MS/ALARM_OFF_MS/ALARM_GAP_MS` 与 `CD_ON_MS/CD_OFF_MS`；闹钟 6 下、倒计时 2 下由 `beep_cnt` 判断。
   改响声长短只动这几个常量，别动状态机。
5. **显示扫描**：`display_ctrl.v` 在 `tick_1khz` 里做 `dig_n <= ~(8'b00000001 << scan_idx)`，1 ms 换一位、8 ms 扫完一轮。
   扫描太快会暗、太慢会闪，1 kHz 是折中值。

### 第 07 章 Verilog 语法速查

1. **wire 与 reg**：`wire` 用 `assign` 或模块输出驱动；`reg` 在 `always` 里赋值。
   综合后 `reg` 不一定真是寄存器：组合 `always @(*)` 里的 `reg` 会变成 LUT。
2. **阻塞与非阻塞**：时序 `always @(posedge clk)` 用 `<=`；组合 `always @(*)` 用 `=`。
   混用最典型的后果是“仿真对、上板错”，因为仿真和综合对更新顺序的理解不同。
3. **位宽**：24 位 BCD 等于 6 个 nibble；`cursor` 3 位；`key_press` 8 位；常量带位宽（`26'd0`）避免截断警告。
   拼接 `{ht,ho,mt,mo,st,so}` 的顺序决定哪 4 位是“时十”。
4. **拼接与可变位选**：`{ht,ho,mt,mo,st,so} = t;` 是拆分；`t[23:20]` 是时十位；`disp[(scan_idx*4) +: 4]` 是可变位选，`+:` 表示向上取 4 位。

### 第 08 章 仿真实战

1. **testbench 结构**：`timescale` → 无端口 module → `reg` 激励 / `wire` 观测 → DUT 例化 → `always #10 clk50 = ~clk50` → task → `initial` 主流程 → `$dumpfile/$dumpvars` → 结尾统计 PASS/ERROR。
   对应文件 `sim/tb_digital_clock_top.v`，82 条断言分布在 TEST 1~10 里。
2. **加一个测试用例**：在 `initial` 末尾加一段 `TEST n`，用 `press_key(7)` 进设置、`check32("名字", 实际, 期望)` 断言、`errors` 自动累加。
   不用改 `run_sim.bat`，它已经用 `for` 循环编译 `..\rtl\*.v` 和 testbench。
3. **断言为什么用 `!==`**：`check32` 用 `!==` 比较，X/Z 也算错；用 `!=` 的话 X 可能被当成“不等于”而漏报。
4. **SIM_FAST 的作用**：`#(.SIM_FAST(1))` 把 1 秒缩成 1000 个 50 MHz 周期，82 条测试才能在几秒内跑完；上板必须用 0。
   改仿真时长只动这个参数，不要改 RTL 里的分频常量。

### 第 09 章 断点与调试

1. **断点怎么设**：在 ModelSim 的 Source 窗口行号左侧双击，或在 Transcript 里用 `bp` 命令；`run -all` 会停在断点，`cont` 继续。
   断点适合看“某个状态跳转前一刻”的现场。
2. **单步看什么**：`step` 进入 function/task，`stepover` 不进入，`stepout` 跳出当前层。
   重点看 Signals 窗口里的 `mode`、`setting`、`cursor`、`beep_cnt`、`expire_pulse`。
3. **断点放哪一行**：放在状态跳转那行，例如 `key_ctrl.v` 的 `if (key_press[7])`、`countdown.v` 的 `else if (tick_1hz && run_reg)`，一次能看清跳转前后的值。
4. **断点太多会拖慢**：每个断点都停一次，82 条测试可能停几百次；用条件断点或 `when` 表达式过滤，或者干脆用 `$display` 打印。
5. **调试顺序**：先看 `tick` 有没有，再看状态机有没有动，最后看数据对不对；从上游往下游查，别一上来就盯显示。

### 第 10 章 上板与排错

1. **下载失败**：先查 USB 口（核心板 USB-B）、驱动（设备管理器）、模式 No.9，再点 `Auto Detect`；细节见 10.6 第 14 条。
   不要一失败就改代码，先证明 JTAG 链是通的。
2. **数码管不亮**：先看 LED1 闪不闪，区分全局还是显示链；再查模式 No.9 和 `seg_n`/`dig_n` 引脚，见 10.6 第 1、2 条。
3. **下载成功但不运行**：检查 `Program/Configure` 有没有勾、有没有点 `Start`、下载的是不是最新 `.sof`，最后按 K1 复位。
4. **时间不走**：LED1 正常闪说明时钟好，查 `tick_1hz` 到 `time_counter` 的连线；用 SignalTap 触发 `tick_1hz`，看 `time_bcd` 变不变。
