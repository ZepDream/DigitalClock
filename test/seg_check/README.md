# seg_check：数码管段序 / 位序自检工程

这个独立小工程只做一件事：**用肉眼确定实验箱“模式 9”数码管的段序和位序**，
从而判断主工程的 `DigitalClock.qsf` 里 `seg_n[7:0]` / `dig_n[7:0]` 该怎么锁。

它不参与主工程编译，也不影响 `rtl/`。

## 怎么用

1. 打开本目录的 `seg_check.qpf`（或在 Programmer 里直接加 `output_files/seg_check.sof`）；
2. 实验箱模式拨到 **No.9**，下载，按一下 K1；
3. 先确认核心板 **LED1 以 1 Hz 闪烁**（说明程序在跑），然后看 16 秒，它会自动走两轮：

| 时间 | 行为 | 用来判断 |
|---|---|---|
| 第 0~7 秒 | 只使能“数码 1”（最右），`seg_n` 每次只拉低 1 位，从 `seg_n[0]` 到 `seg_n[7]` 依次 | 哪个 `seg_n` 位对应哪一段；一次亮 1 段说明段是低有效，亮 7 段说明高有效 |
| 第 8~15 秒 | 八段全亮（应显示 `8.`），`dig_n` 每次只拉低 1 位，从 `dig_n[0]` 到 `dig_n[7]` 依次 | 哪个 `dig_n` 位对应哪一位；一次亮 1 位说明位选低有效，亮 7 位说明高有效 |

## 本板实测结论（2026-11）

| 现象 | 结论 |
|---|---|
| 第 0~7 秒只亮 1 段，顺序是 a→b→c→d→e→f→g→dp | 段**低有效**；`PO[0]=a, PO[1]=b, …, PO[6]=g, PO[7]=dp` |
| 第 8~15 秒一次只亮 1 位，从最右往左是 数码1→数码8 | 位**低有效**；`PO[8]=数码1 … PO[15]=数码8` |

也就是说：**位序和手册一致**，但**段序与手册正文相反**（手册写 `PO[7:0]` = g,f,e,d,c,b,a,point）。
因此主工程的 `.qsf` 里 seg 的 8 条引脚按反序锁定：

```text
seg_n[7] = g  -> PO[6] = D1
seg_n[6] = f  -> PO[5] = B3
seg_n[5] = e  -> PO[4] = A3
seg_n[4] = d  -> PO[3] = B5
seg_n[3] = c  -> PO[2] = A5
seg_n[2] = b  -> PO[1] = B7
seg_n[1] = a  -> PO[0] = B6
seg_n[0] = dp -> PO[7] = C2
```

按手册正文（`seg_n[7]`→`PO[7]`=C2）锁会显示成“字符像但缺段/多段”的乱码。

## 换板子/换实验箱时

先跑一遍这个工程核对段序，再改 `.qsf`。本工程故意保留“按 PO 原始位序”的接法，
所以它的引脚分配**不需要**跟着主工程改——它测的就是 PO 位的物理含义。
